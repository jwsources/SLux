Shared spec

Style spec for every prompt

Each Copy button adds this spec in front of its prompt. It sets colour, type, spacing and states, so the output matches the previews.

WOW FACTOR / EXECUTION CONTRACT — APPLY TO ALL GENERATED SCREENS
Create a genuinely premium, production-quality, executive-grade interactive application, not a wireframe, generic admin template, static mockup or collection of oversized tiles. Visually comparable in attention to detail to a polished enterprise mission-control interface. Build the real HTML/CSS/JS/SVG experience, not an image of a dashboard.
VISUAL SYSTEM: Use ServiceNow-inspired deep navy #032D42 / #052436 and restrained emerald #63DF4E, cyan #38BDF8, amber #FBBF24 and red #F87171. Background has layered subtle radial glow and quiet blueprint/grid texture. Semi-transparent graphite/navy cards with ultra-thin borders, restrained inner highlights and elegant depth; NO thick neon borders, noisy gradients, or excessive glass blur. Typography ServiceNow Sans when available, system fallback; near-white text on all dark surfaces, never black text on dark backgrounds. Aim for WCAG AA normal-text contrast. Headline 24–30px, section titles 15–18px, body 12–14px, metadata 11–12px, headline KPIs 26–34px; compact but legible, with clear hierarchy.
LAYOUT: First viewport designed around 1440×900 desktop with useful content immediately visible. 12-column grid; 20–24px outside margins; 12–16px gaps; cards 14–18px padding, 12–16px corner radius; disciplined alignment, generous negative space, no huge empty areas, no giant charts or oversized typography. Limit headline metrics to 4–5; reserve ~45% of visual emphasis for the primary focal visualization, ~30% for insight and comparison, ~25% for action/context. At 1024px reflow to 2 columns, at 720px reflow to 1 column with no clipping/horizontal scroll. Maintain content density intelligently.
WOW COMPOSITION: Add a polished application chrome with logo/product title, short contextual subtitle, last-updated label, working date/period controls, concise live/sample status, 1 focal hero visual, compact KPI band, and meaningful insight/action surface. Craft bespoke crisp SVG icons and refined chart paths; use small purposeful status pulses, count-up or path-draw entrances (200–700ms), smooth hover/selection and subtle alert motion. Motion must clarify change, never distract; respect prefers-reduced-motion. Do not treat every chart as a static image.
FUNCTIONALITY: Every visible tab, filter, date selector, legend toggle, card selection, action button and drilldown must work with local state; cross-filter when appropriate. Tooltips must report accurate values and units. Include sample scenarios showing healthy, warning and critical states. Use deterministic, internally consistent, realistic sample data; clearly mark Sample/Demo and distinguish simulated streams from verified real integrations. No invented live feeds, data sources, AI results or operational claims. Handle zero data, empty results, loading, long labels, keyboard focus and responsive layouts.
DELIVERABLE: Return a complete runnable, self-contained index.html with inline CSS and JavaScript and SVG-based visualizations (no external required libraries or assets). Ready for GitHub Pages deployment and iframe embedding. Keep all paths relative; avoid features blocked by iframe sandbox where possible. Add sane iframe height/overflow behavior, semantic controls, accessible labels, and a usable static fallback. No TODOs, placeholders, fake non-working controls, implementation essay, or blank sections. Deliver runnable code, not a textual description of the intended UI.
FINAL QUALITY GATE: Before finishing, mentally review at 1440×900 and 390×844; confirm contrast, text legibility, chart accuracy, visual balance, no horizontal overflow, sample-data honesty and full interactivity. Refine design until it feels like a unified custom-designed executive experience rather than a default dashboard.

Gauge

Headline
Use
One metric against one clear target
Avoid
Many metrics at once (wastes space)

Build a radial gauge for [audience] showing [metric] against [target] for [period]. Match the preview: a 180-degree arc, 10px stroke, grey track, coloured fill to the value, a white tick at the target. Centre: value in 32px bold, unit in grey, and percent of target in 11px label text beneath. The four parts of a prompt that works

Most weak dashboards come from a prompt that names no audience, no question, and no visual. Give these four things in two or three lines and the output lands close to the first try.

1

Audience

Who looks at it: an executive, a team lead, an analyst.

2

Question

The one thing the screen must answer.

3

Visuals

Name the chart types, or the number of KPIs.

4

Constraint

Scope and size: one screen, UI only, max five slices.

Vague

"Make me a sales dashboard."

No audience, no question, no visuals. Expect generic charts and a lot of rework.
Small, but specific

"Executive sales dashboard for regional leads, answering: are we on track this quarter? Four KPIs (revenue vs target, win rate, pipeline coverage, average deal size). Monthly revenue trend with a target line. Top 10 regions as ranked bars. One screen, UI only."

Four parts present. Each visual answers a sub-question, so nothing is decorative.
Before you ship it

Best practices

Ten checks that separate a dashboard people open from one they screenshot and forget.

01

Start from the question

Write the question the screen answers before choosing any chart.

02

Title with the insight

"Revenue is 6% below plan" beats "Revenue by month". Let the title carry the message.

03

Cap the screen

Four KPIs above the fold, and three to five visuals per view. More than that and nothing stands out.

04

Match chart to data shape

Compare with bars, trend with lines, part-to-whole with a donut, density with a heatmap.

05

Always show a comparison

A number alone means little. Show it against target, last period, or the average.

06

Sort and start at zero

Rank bars by value, and begin bar axes at zero so lengths stay honest.

07

Colour means one thing

Reserve green, amber, and red for status. Never use them for decoration.

08

Never rely on colour alone

Pair every status colour with a label or icon, so it still reads for colour-blind users.

09

Label directly

Put labels on the data rather than sending the eye to a legend. Avoid 3D and dual axes unless essential.

10

Run the five-second test

Show it to someone for five seconds. If they cannot say what it says, rebuild it.
